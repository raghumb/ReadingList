Lets build a simple system which allows multiplication of two numbers. If we have to support this using natural language, we will need the system to do the following:

1. The user asks the question (a natural language text, asking something like 'what is the product of 5 and 6?')
2. The model requests `multiply(5,6)`.
3. System runs the function.
4. System gives the result back to the model.
5. The model answers the user.

Note:

What other values are supported for 'type' during tool call. one value is 'function'?
For the Chat Completions API, the current documented tool-call types are: 


type	Meaning	Structure
"function"	Call a named function with structured arguments	function: {name, arguments}
"custom"	Send input to a custom tool using free-form text or a specified grammar	custom: {name, input}
For example, a custom tool call looks like this:

{
    "id": "call_456",
    "type": "custom",
    "custom": {
        "name": "run_command",
        "input": "list files in the current directory"
    }
}

Unlike the function type, which provides JSON-encoded arguments, the custom type supplies an input string. Your runtime must understand how to handle that custom tool.
What about web search, shell, and MCP?
These are also available in the broader OpenAI platform, but they are not additional values you can simply put into the Chat Completions tool_calls[].type field. They use their own tool definitions and API-specific execution flows.
